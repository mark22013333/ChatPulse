ChatPulse 上手指南

Google Chat 的摘要與 Mention 收件匣。兩個入口共用同一套後端： MCP Server（在 Claude Code / Desktop 對話中直接用）與 Web 儀表板（完整功能，含 Mention 收件匣與 Draft Reply）。

🧭
不知道從哪開始？ 裝完之後跑 ./scripts/doctor.sh，它會逐項告訴你還缺什麼、下一步做什麼。
讀訊息與發訊息用的都是你本人的 Google 身分，這個系統沒有機器人； 任何送出動作都需要二次確認。
🚪 兩個入口，先決定你要用哪個

🤖 MCP Server

在 Claude Code / Claude Desktop 的對話裡直接用自然語言操作。

  • 安裝最輕：只要 Python，連前端都不必載入。
  • 能做：列群組、抓對話、產摘要、發訊息、查供應商。
  • 不能做：Mention 收件匣與 Draft Reply（那兩個在儀表板）。
  • 安裝：./scripts/install-claude.sh

🖥️ Web 儀表板

瀏覽器介面，功能完整。這是「被 @ 了不漏接」的那一半。

  • 額外需要：沒有。畫面已隨專案附上，不需要 Node.js。
  • 能做：MCP 的全部，加上 Mention 收件匣、Draft Reply、參考群組。
  • 啟動：./chatpulse.sh web → http://localhost:8000
🧠 AI 供應商（摘要與 Draft Reply 需要）

只讀群組與訊息不需要 AI；要產摘要或草稿才需要。目前兩個實作：

供應商需要什麼說明
claude_cli
預設		 本機裝好並登入 Claude Code 直接用你現有的訂閱，不需要任何 API key。終端輸入 claude 能進對話就代表可用。
gemini GOOGLE_API_KEY 免費層每天只有 20 次請求，多人共用會當天用完。

另有兩個別名：claude（目前解析為 claude_cli）與 auto（依序試 claude_cli → gemini，挑第一個可用的）。
想知道你機器上哪個可用：./scripts/run_summary.sh --list-providers， 或在 Claude 裡問「列出目前可用的 AI 供應商」。

🔑 快速搞懂憑證機制（同事分享必讀）

🏢 client_secret.json（團隊共用）

代表這套「Google Chat 助手應用程式」。代表本專案已在公司 GCP 專案完成登記。

  • 可以分享給同事：直接提供給同事放進 config/ 資料夾。
  • 免除繁瑣設定：同事不需要每個人都去開一個 GCP 專案。

👤 google_chat_token.json（個人專屬）

代表使用者的個人身分授權。決定了 AI 能看見哪些私訊與群組空間。

  • 絕不能共用或複製：複製別人的 Token 會看到別人的私訊！
  • 每位同事登入一次：執行一鍵安裝精靈時會自動跳出瀏覽器完成授權。
⚡ 最強推薦：Claude Code 一鍵指令安裝

🔥 只要一行指令，自動授權並完成註冊！

就像安裝 Claude Code Plugin 一樣，同事只要把 client_secret.json 放入專案後，在終端機執行這行指令： 

./scripts/install-claude.sh

這支指令會自動：
1. 檢查並自動準備 Python / uv 依賴環境。
2. 自動開啟瀏覽器讓同事登入 Google Workspace 帳號。
3. 調用 claude mcp add --scope user google-chat 直接將工具註冊進 Claude Code。
4. 執行完畢後立即生效（健康檢查狀態：✔ Connected）！

🚀 傳統手動流程（適用 Claude Desktop）
1 複製專案與放置共用憑證

向 Mark（或專案維護者）取得專案與 client_secret.json，放進專案設定目錄： 

# 專案路徑結構
google-chat-bot/
└── config/
    └── client_secret.json   <-- 放置在此處
2 執行一鍵新手精靈（自動登入授權）

在終端機中執行精靈指令，系統將自動開啟瀏覽器跳出 Google Workspace 授權頁面： 

cd google-chat-bot
./scripts/setup.sh
💡
瀏覽器彈出時，請點選您的公司 Google Workspace 帳號並點選「同意授權」。完成後終端機會自動產生專屬您的個人 Token 與 MCP 設定！
3 設定 Claude Desktop / Claude Code
✅
用 Claude Code 的話這步可以跳過——./scripts/install-claude.sh 會自動幫你跑 claude mcp add 並帶上正確的絕對路徑。下面的手動 JSON 是給 Claude Desktop、或安裝腳本失敗時備援用的。

將以下 JSON 內容加入您的 Claude 設定檔中。 請把 /你的路徑/ 換成你實際 clone 的位置 （在專案目錄下執行 pwd 就會印出來）： 

{
  "mcpServers": {
    "google-chat": {
      "command": "uv",
      "args": [
        "run",
        "--with", "mcp",
        "--with", "google-api-python-client",
        "--with", "google-auth-oauthlib",
        "--with", "google-auth-httplib2",
        "--with", "requests",
        "--with", "cryptography",
        "python3",
        "/你的路徑/google-chat-bot/mcp_app/mcp_server.py"
      ]
    }
  }
}
設定檔位置：
• Claude Desktop: ~/Library/Application Support/Claude/claude_desktop_config.json
• Claude Code (CLI): ~/.claude.json
⚠️
只有走 Gemini 供應商的人才需要多這一步： Claude Desktop 是 GUI 程式，不會讀取 ~/.zshrc， 所以環境變數要寫在設定裡。在上面的 "google-chat" 區塊內補一段： 
"env": { "GOOGLE_API_KEY": "你的金鑰" }
預設的 claude_cli 供應商不需要這一步（它用你本機 Claude Code 的登入狀態）。
🛠️ MCP 核心工具清單 (AI 可直接調用)
工具名稱 (Tool Name) 功能說明 主要參數
list_chat_spaces 列出使用者加入的所有群組與空間 search（關鍵字篩選，如 'BU2', '北市府'）
fetch_chat_messages 抓取指定空間的對話列表（由舊到新排序） space_name_or_id, limit（預設 50，可用範圍 1~1000）
summarize_chat_space 提煉對話主題、決議與 Action Items。三種風格輸出的章節結構不同： general 通用／technical 技術細節（含「已排除的假設與排查過程」）／ action_only 只要待辦 space_name_or_id, limit, style, post_to_chat（是否回推群組）, provider（指定 AI 供應商，留空用預設）
list_ai_providers 列出目前有哪些 AI 供應商、各自可不可用，以及不可用的原因與修法 （無）
send_chat_message 在指定 Google Chat 群組發送訊息（以你本人的身分，不是機器人） space_name_or_id, message_text

這五個是 MCP 入口的全部工具。Mention 收件匣與 Draft Reply 不在這裡—— 它們需要知道「你是誰」以及維護處理狀態，只在 Web 儀表板提供（見下一節）。

🖥️ Web 儀表板：Mention 收件匣與 Draft Reply

啟動一行就好，它會自己建 Python 環境、確認畫面備妥、開瀏覽器： 

./chatpulse.sh web          # Windows：chatpulse.bat web

畫面已隨專案附上，不需要 Node.js、不用等建置。跑起來在 http://localhost:8000。
登入：已經授權過的話，在登入畫面按一下「匯入既有憑證」即可， 不會再跑一次 Google 授權。這個按鈕要自己按（儀表板與 MCP 的憑證分開存）， 而且儀表板的登入狀態 14 天後過期，過期再按一次同一個按鈕就好。

📬 Mention 收件匣

跨所有群組找出誰 @ 了你，集中成一份待處理清單。背景每 45 秒輪詢一次。

  • 只認「真的被 @」：「某人被加進群組」與 @全部 廣播都不會算進來。
  • 只有兩種狀態：待處理／已處理。
  • 已知取捨：在手機或 Chat 網頁直接回覆不會自動變成已處理， 需要回來手動標記。這是為了零誤判刻意選的。

✍️ Draft Reply（含參考群組）

針對一則 @ 產生可直接送出的回話，輸出「脈絡分析」與「建議回話」兩段。

  • 參考群組是重點：PM 會 @ 你，正是因為答案不在他看得到的地方。 產草稿時可勾選 1~N 個其他群組一起納入脈絡。
  • 預設不勾任何參考群組，系統不會自動幫你選。
  • 送出需二次確認 → 以你本人身分回到原討論串 → 該則自動標記為已處理。
🔒
你看得到什麼，完全由 Google 的群組成員身分決定。 ChatPulse 不自建權限系統——你沒加入的群組，你的 token 就抓不到。
產出物也是私有的：你產的摘要只有你看得到，即使同事跟你在同一個群組； Mention 與其處理狀態同理。

❓ 常見問題與排錯 (FAQ)

Q1: 推播回群組時失敗，是不是要先把 Bot 加進群組？

不是，不需要邀請任何東西進群組。讀訊息和發訊息用的都是你本人的 Google 身分 （架構決策 ADR-0001），所以只要你在那個群組裡就能發言。 沒有機器人代你發言——API 回讀確認發送者就是你的帳號本人。 （舊版手冊在這裡寫過「把 Bot 加進群組」，那是錯的，已更正——照做只會讓你去找一隻不存在的機器人。）
真正的原因通常是：
• 403 SPACE_FORBIDDEN：你不是該群組的成員，或授權時沒給 chat.messages.create 權限 → 重跑一次授權精靈
• 404 SPACE_NOT_FOUND：群組 ID 打錯，或那個群組你已經退出了
• 401 NOT_AUTHENTICATED：儀表板的登入過期 → 重新登入

Q2: Token 過期了需要手動刪除嗎？

不需要！程式內部具備 Refresh Token 自動刷新機制。只要不是憑證被後台撤銷，背景會自動無感續期。
注意一個例外：刷新只延長效期，不會增加授權範圍。 若儀表板抱怨權限不足，要重跑 ./scripts/setup.sh 重新授權，刷新補不回來。

Q3: 為什麼我送出的訊息旁邊多了一個灰色標籤？

那是 Google Chat 的歸屬標示：只要訊息是透過 API 送出的， Chat 就會在你的名字旁邊顯示這個工具的名稱，像 你 [ChatPulse] 中午12:36 這樣。 官方文件 create-messages 逐字寫著「Chat also attributes the Chat app to the message by displaying its name」， 所以這是設計行為，不是設定錯誤。

• 發話的人還是你本人：API 回讀確認 sender.type 是 HUMAN、user id 是你自己，不是機器人代你發言。
• 關不掉：spaces.messages.create 沒有任何相關參數， 也沒有對應的 scope 或 Console 開關。（精確地說：官方未提供關閉手段， 而不是官方明令禁止。）
• 文字可以改（上限 25 字元），改的是 Chat API 的 App name， 只有專案維護者要做、一次改完所有人適用，而且不需要重新授權：
https://console.cloud.google.com/apis/api/chat.googleapis.com/hangouts-chat?project=PROJECT_ID
