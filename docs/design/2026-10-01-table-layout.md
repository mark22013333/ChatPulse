## §1 這次改什麼、不改什麼

目標是讓 ChatPulse 跟團隊日常使用的內部管理系統有一致的外觀：深藍色 SideNav、白色頂列、分頁 tabs、釘選卡片、篩選列、表格、分頁器。

**判準只有一條：清單型模組改成表格，對話型模組保留主從式。**
Mention → Draft Reply 需要一邊看清單一邊寫回覆，改成整頁表格就得來回跳頁，會拖慢最主要的工作流程；
Space 與工時本來就是「找一筆 → 看細節」，放進表格反而好找。

| 模組 | 處置 | 頂部 tabs（模組內子視圖） |
| :--- | :--- | :--- |
| 摘要工作台 | **改表格** | 全部 Space／有新 Mention／已釘選 |
| 工時草稿 | **改表格**（一列一天） | 本週／上週／未送出 |
| Mention 收件匣 | 保留主從式，只換視覺 | 待回覆／已有 Draft Reply／已處理 |
| 統計、週報、設定 | 只換視覺 | 不加 |

被否決的做法：
- **全部改表格**：Mention 收件匣會失去「清單與 Draft Reply 同時在眼前」這件事，見上面的理由。
- **頂部 tabs 當模組切換**：跟 SideNav 做同一件事，同一個動作兩個入口。
- **只換色、不動結構**：需求是版面結構，不只是配色。

## §2 配色：深藍側欄＋藍色 accent，淺深兩套都重做

- token 仍然只在 `src/index.css` 定義，元件只用語意 token；`lib/tokens.test.ts` 的守門規則一條都不放寬。
- 深色版**不是反相**：SideNav 壓得比主體更暗，才分得出層次；燈號與徽章在深色底另調亮度，對比照 §10.8。
- 語意色（完成／待確認／失敗／尚未開始）與 accent 藍分開，不共用。
- 草稿裡的色值是方向，不是定稿；落到 token 時以對比門檻為準，數字對不上就調色值，不調門檻。

## §3 版面骨架

```
┌──────────┬──────────────────────────────────────────────┐
│ SideNav  │ 頂列：模組標題 ┊ 搜尋框(⌘K) ┊ 深淺切換 ┊ Viewer │
│ 深藍     ├──────────────────────────────────────────────┤
│ 固定寬度 │ tabs                                          │
│          │ 釘選卡片列（僅摘要工作台）                    │
│          │ 篩選列 ………………………………………… 共 N 筆      │
│          │ 表格                                          │
│          │ 分頁器 …………………………………………… 每頁 N 筆  │
└──────────┴──────────────────────────────────────────────┘
```

- **SideNav 固定寬度，不做收合。** 主體從三欄變單欄後寬度已經充裕；只有 6 個模組，另有 `g s`／`g m` 快速切換。收合要多背 tooltip、焦點、偏好儲存三份測試，換來的價值不夠。
- **頂列不放通知鈴。** 通知中心需要事件模型與已讀狀態，是新功能不是改版；放一個不會動的鈴等於佔位元件。Mention 數量已經在 SideNav 的徽章上。
- **搜尋框是 CommandPalette 的入口**：點擊或 ⌘K 開同一個面板，不另做一套頁內搜尋（兩套搜尋結果會不一致）。
- 小於 768px 維持 `SmallScreenNotice` 與既有 P7 響應式，這次不動。

## §4 表格型模組

### 4.1 點一列 → 整頁切到詳情

- 沿用既有路由：`#/summary` 是清單、`#/summary/:key` 是工作區；工時同理。
- `MasterDetailBack` 從「只在 < lg 出現」改成**所有寬度都出現**，文案「← 返回 Space 清單」。
- 收起來的表格用 §7.2 的手法（`pointer-events-none absolute inset-0 -z-10 opacity-0` ＋ `inert`，照 `AppShell.tsx` 現有寫法），🔴 **不准用 `display:none`**——規格 P7 實測它會讓捲動位置跳掉；返回時篩選、排序、頁碼、捲動位置都要還在。

被否決：右側抽屜（Summary 有長篇串流與證據欄，塞不下；而且是一套新的焦點管理）、列下展開（列高忽大忽小，分頁器位置跟著跳）。

### 4.2 分頁、排序、篩選

- 分頁器預設**每頁 25 筆**，可選 10／25／50，存進偏好（沿用 `feature/list-sorting` 的偏好儲存）。
- 排序沿用 `lib/listSort.ts` 的純函式。
- 🔴 **排序與篩選一律對全部資料做完，再切頁。** 只排當頁 25 筆就是 `CLAUDE.md` 硬規則的「靜默少給資料」：畫面看起來是全部 Space 的排序，實際只有第一頁。要有一條測試用「第二頁才有的資料」當正對照守住。
- 鍵盤 ↑↓ 只在當頁內移動（沿用 `lib/listNavigation.ts`）。被否決：走到頁尾自動翻頁——焦點會突然跳走。
- 篩選列右側顯示「共 N 筆」，N 是篩選後的總數，不是當頁筆數。

### 4.3 摘要工作台的欄位

| 欄 | 內容 |
| :--- | :--- |
| ★ | 釘選切換；已釘選的同時出現在上方卡片列 |
| Space 名稱 | — |
| 類型 | 沿用 `lib/format.ts` 的 `spaceTypeLabel`（群組／多人對話／私訊），不另訂文案 |
| 最後活動 | 今天顯示時間，更早顯示日期 |
| 今日訊息、Mention | 數字，`tabular-nums` |
| Summary | 已是最新／有 N 則新訊息／從未產生 |

### 4.4 工時草稿的欄位

一列一天：日期、星期、草稿時數（附比例條）、專案分配、狀態（未產生／草稿／已送出）、燈號。
🔴 **專案分配在產生時一律留空**（ADR-0008 的硬規則），表格顯示「歸屬尚未選擇」，不得顯示系統猜的專案。
