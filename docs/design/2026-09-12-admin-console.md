# ChatPulse 後台介面改版

> 2026-09-12。這一輪建立在 [`2026-09-09-ui-redesign.md`](2026-09-09-ui-redesign.md) 之上，
> **推翻了它的兩個決定**（見第 5 節），其餘規格繼續有效——尤其是 §17 紅線的其他九條、
> §10.8 的對比門檻、§7.2 的保留掛載手法。

## 1. 為什麼有這一輪

上一輪把介面做成「證據優先工作台」，形態是頂列兩顆膠囊頁籤 ＋ 三欄。功能上沒問題，
但它**擴充不動**：

- 新增一個頂層工作台要改 8 個地方（`route.ts` 的 `Section` 聯集、`AppShell` 三處手寫的
  `<Pane>` 配對、`TopBar` 的頁籤、`commands.ts` 的「前往」清單、`hotkeys.ts` 的 `g` 前綴表、
  新 store、`useRouteSync`）。漏掉任何一處都不會編譯失敗，只會在執行期少一塊。
- 頂列的橫向空間放不下五六個以上的頁籤。

而後續規劃要加統計／分析儀表板、知識庫歷史檢索，以及一個讀 Google Chat 與專案 git 紀錄
產出「一週工作事項與工時」的週報模組。

## 2. 方向怎麼定的

沒有直接動手。先出三版真實視覺 mockup（同一份 spec、同一批真實內容，只換設計詮釋），
截圖給使用者選：

| 版本 | 導覽 | 卡片 ΔL | accent |
|---|---|---|---|
| v1 克制 | icon rail 56px | 0.010 | 銅 h50 |
| v2 標準 | 200px 常駐 | 0.025 | 琥珀 h70 |
| v3 密實 | icon rail ＋ 標頭帶 | 0.040 | 赤陶 h40 |

**選定 v1**，並一併採納兩項調整：ΔL 抬到 0.02~0.025、修 `--caution` 的對比。
完整記錄（含三版各自的弱點與驗證結果）在 `dashboard/frontend/design-demos/direction-approved.md`，
設計稿與 spec 在同一個目錄，截圖可用該目錄的 `shoot.cjs` 重跑
（副檔名是 `.cjs` 不是 `.js`——`dashboard/frontend/package.json` 有 `"type": "module"`，
放在它底下的 `.js` 會被當成 ES module，用 `require` 會直接炸）。

三版都做到的事值得留著：狀態的第一區分是**線型與字符**、不用中點 `·`、
全站最大的字是 Token 用量那個數字、零漸層零裝飾性陰影。

## 3. 設計 token

### 色相 250 → 暖色

表面 h75、前景 h60/h80、規線 h70/h80。中性色的彩度維持原量級（0.002~0.012），
是換色溫不是加一層米色濾鏡。訊號色從藍改為銅 `oklch(0.520 0.125 50)`。

**暖色系最大的風險是三個語意色撞在一起**：accent 若取琥珀 h70 會與 `--caution` 的 h75
只差 5 度，在 3px 邊框或小 chip 上分不出來。銅 h50 與 caution 差 25 度、與 destructive 的
h24 差 26 度，是三者距離最均勻的位置。

### 淺色 ΔL 0.013 → 0.022，深色一格未動

抬的手法是把 `--background` 從 0.985 降到 0.962，**不是**把 surface 往上推：0.998 已經
貼著 sRGB 天花板，再往上 `--raised` 就無處可去（實測 `oklch(0.998 0.002 75)` 已超出色域，
raised 收在 0.995）。代價是背景變暗會讓深色前景的對比下降，逐一重算後只有 `--fg-subtle`
需要動（0.55 → 0.521）。

深色**明度一格都沒動**。那是 2026-09-10 依實機回報「頁面不要做全黑」逐項量出來的，
而且它的 ΔL 本來就有 0.034。改版初稿 v1 的深色背景是 0.175，比那次修正**之前**的 0.189
還暗——沒有照抄，就是為了這件事。兩個主題的階層策略因此不再對稱，這是刻意的。

### 驗算

每個前景色 × 四個表面 × 明暗兩主題逐一重算 §10.8 的門檻，全數達標。
`index.css` 註解裡的比值改成**四個表面裡最差的那一個**，不再是只對 `--background` 算的
數字——看起來比舊註解小是口徑變嚴，不是對比變差。

新增 `src/dev/TokenSheet.tsx`（`#/dev/tokens`，僅開發模式掛載，正式建置會被 tree-shake）。
它讀的是 `getComputedStyle` 的**實際渲染值**而不是 OKLCH 理論計算——§3.1 自己就警告過
那是計算值不是量測值。兩者實測一致（最大差 0.03，8-bit 量化誤差），表示沒有色域裁切。

## 4. 模組表與左側導覽

### `src/lib/modules.ts`

「這個 app 有哪些頂層工作台」的唯一事實來源。`Section` 型別由它推導：只有 `status: 'ready'`
的模組才進型別，`'planned'` 的只在導覽上佔一個灰掉的位子。**要上線就把欄位改掉**，
忘了接 `parseHash` 的話 TypeScript 會在 `AppShell` 那裡報出來。

導覽、⌘K 的「前往」清單、`g` 前綴快捷鍵全部吃這張表。

這一層刻意不 import 圖示：`route.ts` 要從這裡拿型別，而它的契約是**零 React 相依、
可在 node 環境直接測**。圖示在 `app/SideNav.tsx` 才接上。

**新增一個工作台現在要做的事**：模組表加一筆 ＋ 寫該模組的畫面本體 ＋ 在 `parseHash`
加一個分支解析它自己的網址參數。最後一項沒有抽象掉是刻意的——每個模組的參數形狀
本來就不同（Space key／mention id ＋ merge／settings tab ＋ id），硬抽象會更難讀。

### `src/app/SideNav.tsx`

照 §10.2 用 `<nav>` ＋ `<a href>` ＋ `aria-current="page"`，**不補 tablist 語意**。
改版前的頂列頁籤是 `<button onClick>`，那是偏離規格的；順手改回來，中鍵開新分頁、
複製連結這些原生行為也跟著回來。

展開狀態是**三態**：`null` 代表沒手動設定過，交給 CSS 斷點（≥1536 展開）；手動切換過
才固定並記進 localStorage。少了 `null` 這一態，沒表示過意見的人就會被迫接受某一種預設，
而這個 app 在 1440 與 1920 下的合理預設本來就不同。

收合態 56px，**圖示下方放兩字中文標籤**。tooltip 是 §17 紅線第 8 條禁止的，而且對鍵盤與
觸控使用者不可達。尚未上線的模組收進虛線群組框，標籤下加點線底線（點線＝缺值，
與摘要章節的規線同一套線型語意）。

### 頂列瘦身

品牌、切換、設定、主題、登出都搬進導覽，`TopBar` 只留「你在哪裡」與全域動作。
麵包屑不顯示 Space 名稱：主內容區已經有大標題，再寫一次是重複，而且要拿名稱得訂閱
整份 436 筆清單，頂列會被清單變動帶著重繪。

## 5. 推翻了上一輪的哪兩個決定

1. **§3.2「這一版的分群靠規線而不是填色，把階層拉開等於改成卡片式——那是重新設計，
   不是這次要做的事」**：這一輪就是做了那件事，但**只在淺色**。深色的 0.034 本來就夠。
2. **§17 紅線第 3 條「既有 store／lib 只准加、不准改」**：對 `route.ts`／`AppShell`／
   `TopBar` 解除。那是上一輪的過程紀律，目的是保護當時的 159 項測試；這一輪改拿
   「測試零減少、零失敗」當真正的把關（實際規模已成長到 554 項 / 37 檔）。
   **其餘九條紅線全部繼續有效。**

## 6. 響應式

| 寬度 | 導覽 | 其餘 |
|---|---|---|
| ≥1536 | 200px 展開 | 三欄常駐 |
| 1280–1536 | 56px icon rail | 三欄常駐（主內容約 616px） |
| 1024–1280 | 56px icon rail | 兩欄 ＋ 證據抽屜 |
| 768–1024 | 56px icon rail | 主從切換，證據仍是抽屜 |
| <768 | — | `SmallScreenNotice` |

導覽一律不參與主從切換：它是「有哪些模組」，與「這個模組裡你在哪」正交。

## 7. 已完成與未完成

**已完成**（三個 commit，每個都跑過 554 測試 / typecheck / 建置蓋章）
- 設計 token 換色與階層
- 模組表、左側導覽、頂列瘦身、⌘K 與快捷鍵接上 registry
- 摘要工作台的表面分層（工具列 raised、產出與 Action Items 成為同一套語法的卡片）

**未完成**
- Mention 收件匣、草稿回覆區、證據欄、設定中心**尚未套表面分層**。
  它們沒有設計稿，刻意留到摘要工作台的語彙確認可用之後再推廣。
- `AppShell` 的三處 `<Pane>` 仍是手寫配對，尚未改成 registry map ＋ lazy mount。
  模組只有兩個時這不是痛點，加到第三個時再做。
- `SpaceList` 那一側仍用中點 `·` 分隔，與 §2.2 原則 7 衝突（既有漂移，不在本輪範圍）。
- 語意色雙軌（`text-muted-foreground` 137 次 vs `text-fg-dim` 41 次）尚未收斂。
- **E2E 未實跑**：需要啟動服務並用 Google 帳號登入。選擇器已更新為 `href` 與
  `aria-current`（不依賴 class 或文字，因為導覽收合時顯示的是兩字短標籤），
  四個檔語法檢查通過，但未經真實執行驗證。
